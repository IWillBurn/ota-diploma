## Требования к артефактам (критерии приёмки)
* **Воспроизводимость:** одна команда (`make bench` или `docker compose up`) даёт ту же матрицу. Версии реализаций зафиксированы (коммиты или релизы), seed задан.
* **Трассируемость:** каждая ячейка матрицы ссылается на сценарий, сценарий на ID угрозы, угроза на пункты спецификаций и требований.
* **Валидность:** контрольная реализация обязана получать FAIL там, где он ожидается, а честный прогон обязан давать PASS (baseline). Иначе прогон считается недействительным.
* **Лицензия:** Apache-2.0 для кода, CC BY 4.0 для каталога и данных. Это совместимо с tuf-conformance (MIT OR Apache-2.0).
* **Артефакт-бейджи:** если статья пойдёт на конференцию с artifact evaluation (USENIX, ACM), упаковать A1–A10 под критерии Available / Functional / Reproduced.
