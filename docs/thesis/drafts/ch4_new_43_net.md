### 4.3.12 Сетевые атаки на A/B-апдейтеры

До сих пор A/B-апдейтеры ставили артефакт из локального файла, и угрозы доступности для них стенд не испытывал. Сценарии `net-*` ставят артефакт по сети с сервера-нарушителя на хосте (`otabench/bundleserver.py`). Гость получает сеть QEMU в режиме user и видит loopback хоста как `10.0.2.2`; артефакт `v2` один раз выгружается из гостя на хост и кэшируется. Сервер поддерживает запросы Range и режимы табл. 4.17е. Адаптер получил операцию `install_url`: у SWUpdate это встроенный загрузчик (`swupdate -d "-u URL"`) с параметрами по умолчанию, у RAUC 1.15.2 — потоковая установка (`rauc install URL`), для которой бандл пересобран в формате verity и загружен модуль nbd (вариант `stream`). Политика стенда та же, что в клиентском контуре: медленная отдача должна прерываться за 120 с, бесконечные данные — не читаться неограниченно (лимит ожидания 300 с).

*Таблица 4.17е — Установка по сети с сервера-нарушителя*

| Сценарий (режим сервера) | Угроза | SWUpdate 2024.12.1 | RAUC 1.15.2, потоковая установка |
|---|---|---|---|
| `net-ok` (честная отдача) | — | PASS | PASS |
| `net-tamper` (инвертирован байт посередине) | OTA-AUTH-01 | PASS: `inflate failed`, установка отклонена, загрузчик не тронут | PASS: dm-verity не пропустил изменённый блок (`Input/output error`), установка отклонена, загрузчик не тронут |
| `net-drop` (соединение рвётся на середине) | OTA-NET-01 | PASS: докачка `Range: bytes=156999936-` в той же установке | PASS: обрыв на середине, загрузка продолжена запросами Range (9062 запроса) и завершена |
| `net-slow` (после первой четверти 64 Б/с) | OTA-DOS-04 | **FAIL**: за 150 с не прервал загрузку | **FAIL**: за 150 с не прервал загрузку (один запрос Range висел 147 с), загрузчик не тронут |
| `net-endless` (после артефакта — данные без конца) | OTA-DOS-02 | PASS по ограниченности чтения; отчёт — код 1 (неудача), хотя загрузчик уже переключён (воспроизведено в трёх прогонах) | PASS: после 3,4 МиБ сверх запрошенного диапазона установка прервана за 6 с, загрузчик не тронут |

**Ложное сообщение о неудаче у SWUpdate.** Когда после целого `.swu` сервер продолжает слать данные, SWUpdate ставит обновление полностью и переключает загрузчик (`ORDER=B A`, `B_OK=1`, `ustate=1`), прекращает чтение примерно через 3,4 МиБ, но завершается с ошибкой канала загрузки (`Writing into SWUpdate IPC stream failed`, код 1). Устройство сообщает о неудачном обновлении, которое уже применено и загрузится после перезагрузки. Неограниченного чтения нет, поэтому вердикт по OTA-DOS-02 — PASS, а расхождение отчёта и состояния стенд записывает отдельно (`status_mismatch`). Для системы управления парком это ошибка учёта: устройство будет считаться не обновлённым.

**Медленная отдача.** С параметрами загрузчика по умолчанию SWUpdate не прервал загрузку на 64 Б/с за 150 с — та же картина, что у python-tuf и go-tuf (п. 4.2.6); защиту должен настроить интегратор. Потоковая установка RAUC 1.15.2 тоже продолжала загрузку через 150 с (`pilot-ab-20261102-100425`, после первой четверти бандла один запрос Range на 12 КиБ висел 147 с), и настроить здесь нечего: потоковый клиент задаёт только тайм-аут соединения 20 с и тайм-аут запроса nbd 300 с (`src/nbd.c`), а в разделе `[streaming]` параметров времени нет. Ограничить время установки может только внешний агент обновления.
